Developer integration
Wrap the functions your agent can call.
The returned guarded registry—not raw handlers—must be connected to the agent. The working Python example below requests human confirmation for a fictional email; the browser sandbox uses its own local approval selector.

      

        

          
Fail-closed toolsUnlisted functions are denied before execution.

          
Approval-required actionsState-changing tools can require an explicit approval callback.

          
Explicit destination rulesSelected URL arguments must match configured HTTPS hosts; this is not a network sandbox.

          
Tested model-tool interfaceAn OpenAI-compatible dispatcher and bounded model loop are available in the Python SDK.

from agentshield_guard import AgentShield, ToolPolicy

# Safe, fictional handlers: no email delivery.
def read_document(id):
    return {"id": id, "text": "Synthetic note"}

def send_email(to, body):
    return {"simulated_only": True, "recipient": to}

# Your app must ask a real human, never the LLM.
def human_approval(tool, args):
    answer = input(f"Approve {tool} for {args['to']}? [y/N] ")
    return answer.strip().lower() == "y"

shield = AgentShield(
    ToolPolicy(
        read_only_tools={"read_document"},
        approval_tools={"send_email"},
    ),
    approve=human_approval,
)
guarded = shield.wrap_registry({
    "read_document": read_document,
    "send_email": send_email,
})

print(guarded["read_document"](id="sample-1"))
print(guarded["send_email"](
    to="demo@example.org", body="Synthetic only"
))
